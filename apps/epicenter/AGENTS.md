# Epicenter

Read the [app README](README.md) for the existing desktop implementation and
the apps it bundles. [Shared vocabulary](../../docs/CONTEXT.md) names the
chosen direction; the linked ADRs record its decisions. Local constraints below
protect the existing implementation while it remains in use.

## Shape

- Epicenter compiles its own pages from the closed `BuiltInApp` table in `src-tauri/src/lib.rs`: Settings (`home`) and the Folders window. It bundles Todos, Capture, Honeycrisp, and Whispering from their own folders under `apps/` through the closed `BundledApp` table in `src-tauri/src/bundled_apps.rs`, which names each app's page, default folder, window label, capability, and build. The source installer is deleted: no repository clone, app manifest, approval, local app build, or second app registry. Do not reintroduce one; a new app is a `BundledApp` row. Clones and builds an earlier version installed stay on disk, never read and never removed.
- Epicenter is an application beside the others, not a shell above them (ADR-0209). Applications keep their own windows and the OS is the launcher and switcher, so do not build an in-app application switcher, a command palette over rows, or anything that indexes rows into an OS search index. Closing Epicenter must leave every other window running. The raw view ADR-0209 described returned as the Folders window over data folders on disk, and Epicenter opens to it (ADR-0537); the host-owned replica it once read stays deleted (ADR-0226). Do not reimport `src/inspect.ts`. Settings is the window labelled `home`; Home Chat is deleted.
- The Folders window is a launcher bound to no folder (ADR-0537, ADR-0647). Its one derived list combines root children, bookmarks, and temporary acceptances by resolved directory identity (ADR-0671, ADR-0672); an existing root default is labelled by its app's title, and listing never creates one. Openings pass a native row ID and require fresh membership, never a display name or a page-supplied directory. It opens a bundled app with `open_bundled_app` (default or listed folder) or `choose_folder_for_app` (the native picker, opened and answered in Rust), a listed folder's editor with `open_folder_editor`, and Settings with `open_home`. These wait for the window's actual outcome. Add a bundled app as a `BundledApp` row, never as another launch command.
- Every window that edits files is bound to one existing directory in Rust through the folder plugin before its WebView exists. Ordinary app-and-folder windows use `FolderExt::open_folder_window`, which owns their identity, reuse, binding, and cleanup; Settings keeps its fixed `home` singleton binding and hide-on-close lifetime. The same app on the same directory reveals that window. A page names no path, scope, or label, and no editor startup URL carries one. Incoming handoff links queue a path for explicit acceptance; their remembered paths are shortcuts, never folder permissions. Bundled app and editor windows are destroyed when they close; do not route them through `ensure_window`, which hides Epicenter's own windows. No bundled app opens Epicenter's records directory. Whispering reads and saves its two AI connection rows there through `whispering_connection_read` and `whispering_connection_set`, by operation, never by path or as a second folder.
- Every page is served by the one scheme handler, `src-tauri/src/scheme.rs`: Epicenter's own pages and each bundled app from `dist/<page>/` at `/<page>/`. A folder editor is the Folders build's `/folders/editor/` route, which selects its page and nothing else. Adding a page is a `BuiltInApp` or `BundledApp` entry plus its build (`build:bundled`, which runs the app's `build:host`), never another resolver, route, or server. The handler holds the containment (no link, nothing outside the directory) and the Content-Security-Policy, which hashes each document's inline scripts; a page served another way loses both.
- Keep document replicas owned by application windows, never by the host (ADR-0226, ADR-0227). Read [application composition](../README.md) and [folder contracts](../../packages/folder/README.md) before changing resource acquisition. App-owned authentication and UI seams use build conditions; do not add runtime detection to those seams.
- Native capabilities grant commands by window label, one file per kind of window: `folders.json`, which grants the launcher no folder command, `home.json`, `bundled-app.json`, which selects `todos:*`, `capture:*`, and `honeycrisp:*` and grants the folder plugin, `whispering.json`, which selects `whispering:*` and grants only what Whispering's page calls, `messages.json`, which selects `messages:*` and grants its bound folder and the fixed Beeper CLI operation, and `folder-editor.json`, which selects `files:*` and grants the folder plugin. Folder pages may use the dialog plugin's message command for close confirmation, but no page gets its file picker. No bundled app's window gets folder history, `account_send`, or model administration. Every file is `"local": true`, because every page is on the scheme. Check the target window's grant when adding a native call; the rule is in the README. Proposed ADR-0402 would replace these files with one host-wide constant; that implementation has not landed.
- Native startup resolves `DesktopPaths` once, before recorder cleanup or any window opens. The recorder, the scheme, and every `epicenter` command the shell runs read that managed state; nothing resolves those paths again. The running bundle identifier scopes data and credentials; explicit directory overrides are resolved by native startup (ADR-0201, amended 2026-09-08).
- Use the shared native default policy in [Application data](README.md#application-data) and [ADR-0672](../../docs/adr/0672-native-app-defaults-are-fixed-reverse-dns-children-of-one-library.md). Do not add per-app home selection, first-use persistence, ownership registries, collision suffixes, or legacy-location lookup. Only fixed defaults may be created; explicitly opened directories must already exist.
- **The host-owned data plane is deleted** (ADR-0226, ADR-0227). Gone with it: the desktop store owner, the `honeycrispMirrorLens` that re-declared another application.s workspace id, the `src/folder/` markdown renderer and its SQLite projection (ADR-0207, ADR-0208), `src/inspect.ts` and the `/api/home/inspect` routes, the `/api/data` proxy and its observation socket, and the durable Home conversation rows. Do not rebuild any of them here. A host serves bundles and brokers credentials; a markdown mirror or a raw view belongs to whoever owns the authority those rows live in.
- Read the relevant application README before changing its file interpretation, save policy, or native ownership boundary.

## Refusals (do not reopen without a new ADR)

- No daemon `mount.ts` as the composition model; the mount path is CLI/projection for one app.
- No MCP for first-party in-process apps; MCP stays the boxed-app airlock (ADR-0073).
- No loose in-process TypeScript tool modules in v1; future scripting starts from an out-of-process runner unless a new ADR explicitly accepts unsafe developer-mode host imports.
- One way to serve a page: the `epicenter-app` scheme, in development as in a release. Do not add a dev server, a loopback server, or Tauri's asset protocol beside it (ADR-0561).
- No source installer (ADR-0611): the shell clones, builds, and approves no app, and reads no app manifest. Bundled apps are built from local source with Epicenter and need no approval. A folder syncs to a hosted repository by `epicenter sync <dir> --to <namespace>/<name>` (ADR-0546).
- No per-app permission prompt or device prompt. An app window runs as Epicenter: shared origin and OS-granted browser device access, and each bundled app's window gets the grant its capability file names. Do not describe the capability file as a sandbox (ADR-0179, ADR-0334).
- Applications never choose the local transcription model. Settings (the `home` window) owns the one active model and its administration; the Folders window holds none of it; apps request transcription and may still choose their transcription route (ADR-0180).
- No new Settings pane and no global rail. Settings is one page; apps are opened from the Folders window. A rail still needs a launchable list large enough to earn it (ADR-0189). Re-adding a Data pane means first deciding how a reader becomes a replica of somebody else's authority, which is an ADR, not a component.
- Do not turn an app-owned file bridge into a generic host command router, synced command table, or transport-adapter framework.
