# Epicenter

One desktop application host. Bun serves the trusted SPAs; the `epicenter`
CLI holds the account (ADR-0556); Rust owns native application mechanisms.

Design authority: [ADR-0190](../../docs/adr/0190-a-build-declares-which-epicenter-owns-its-data-not-which-window-it-runs-in.md) (a compiled application is a declared `dist/<id>` build; its "`epicenter-host` says the host owns its replica" half is withdrawn by ADR-0226, which a build no longer declares at all), [ADR-0209](../../docs/adr/0209-epicenter-is-the-raw-view-beside-its-applications-not-a-shell-above-them.md) (Epicenter is an application beside the others: it shows the data raw, the applications are the crafted views, and the OS is the launcher and switcher), [ADR-0537](../../docs/adr/0537-epicenter-opens-to-your-folders-and-home-becomes-settings.md) (Epicenter opens to the Folders window, which launches apps; Home becomes Settings), [ADR-0189](../../docs/adr/0189-home-launches-applications-into-their-own-windows-and-stays-open-behind-them.md) (one launchable list, one Home-owned launch verb, per-application windows; its Home-as-shell framing is withdrawn by ADR-0209), [ADR-0179](../../docs/adr/0179-an-installed-app-is-an-inert-built-folder-admitted-through-one-static-artifact-boundary.md) (an app window runs with Epicenter's full trust; its installed-app admission boundary is parked with installed apps), [ADR-0180](../../docs/adr/0180-epicenter-has-one-host-owned-active-local-transcription-model.md) (one host-owned active local transcription model), [ADR-0152](../../docs/adr/0152-epicenter-home-is-a-shell-above-workspaces.md) (what Home owns; read its title as history, since ADR-0209 withdrew "above"), [ADR-0151](../../docs/adr/0151-local-workspace-stores-use-owner-first-directories.md) (owner-scoped local stores), and [ADR-0118](../../docs/adr/0118-epicenter-is-one-trusted-bun-hosted-spa-origin.md) (one trusted application origin).

## Shape

- Epicenter ships with no apps installed (ADR-0552). `src/applications.ts` declares what is still compiled in, in one `{ id, title }` shape: the Folders window. Do not compile an app in; an app is a folder in a Git repository, installed and built on this machine (ADR-0540).
- Epicenter is an application beside the others, not a shell above them (ADR-0209). Applications keep their own windows and the OS is the launcher and switcher, so do not build an in-app application switcher, a command palette over rows, or anything that indexes rows into an OS search index. Closing Epicenter must leave every other window running. The raw view ADR-0209 described returned as the Folders window over data folders on disk, and Epicenter opens to it (ADR-0537); the host-owned replica it once read stays deleted (ADR-0226). Do not reimport `src/inspect.ts`. Settings is the window labelled `home`; Home Chat is deleted.
- The Folders window opens an app with one native verb, `open_installed_app`, which waits for the window's actual outcome, and opens Settings with `open_home` (ADR-0537, ADR-0552). Do not add a second app launch command.
- A compiled application is exactly a `dist/<id>` build `COMPILED_APPLICATIONS` declares. `loadStaticAssets` loads every one and the server serves each below `/apps/<id>/` through the shared contained resolver, so adding one is a list entry plus a build script, never another asset field, resolver, or route handler. A declared application that did not build refuses the boot (ADR-0190). Every served application document is held in memory, gated behind a browser session, and hashed into the one CSP. Serving an app's document straight off disk skips all three, and the app boots blank because the browser refuses its own start script.
- Keep document replicas owned by application windows, never by the host (ADR-0226, ADR-0227). Read [application composition](../README.md) and [resource contracts](../../packages/app/README.md) before changing resource acquisition. App-owned authentication and UI seams use build conditions; do not add runtime detection to those seams.
- Current native capabilities grant commands by window label. An installed app's native commands are granted by its app id, through the labels `installed_window_label` makes for it, and list exactly what its page calls; the rule is in the README. Check the target window's grant when adding a native call. Proposed ADR-0402 would replace these files with one host-wide constant; that implementation has not landed. Same-origin HTTP to the Bun host needs no grant.
- Native startup resolves `DesktopPaths` once, before recorder cleanup or sidecar launch. The recorder reads that managed state; Bun receives required `dataDir` and `folderDir` fields in the boot frame. Desktop consumers must not resolve those paths again. The running bundle identifier scopes data and credentials; explicit directory overrides are resolved by native startup (ADR-0201, amended 2026-09-08).
- Every trusted app owns one directory under that root, `apps/<app-id>`, named by the id it is composed under (ADR-0201). Allocation is nominal: the host issues the id and creates nothing, and it reclaims nothing when an app leaves. Apps own their reverse-domain identifiers; the shared grammar validates them. Do not introduce a reservation list without an admission boundary that actually enforces it. Do not give a webview a path into any of it: reach is undecided, and the handle has no filesystem in it (ADR-0181).
- **The host-owned data plane is deleted** (ADR-0226, ADR-0227). Gone with it: the desktop store owner, the `honeycrispMirrorLens` that re-declared another application.s workspace id, the `src/folder/` markdown renderer and its SQLite projection (ADR-0207, ADR-0208), `src/inspect.ts` and the `/api/home/inspect` routes, the `/api/data` proxy and its observation socket, and the durable Home conversation rows. Do not rebuild any of them here. A host serves bundles and brokers credentials; a markdown mirror or a raw view belongs to whoever owns the authority those rows live in.
- Read the relevant application README before changing its file interpretation, save policy, or native ownership boundary.

## Refusals (do not reopen without a new ADR)

- No daemon `mount.ts` as the composition model; the mount path is CLI/projection for one app.
- No MCP for first-party in-process apps; MCP stays the boxed-app airlock (ADR-0073).
- No loose in-process TypeScript tool modules in v1; future scripting starts from an out-of-process runner unless a new ADR explicitly accepts unsafe developer-mode host imports.
- No bundled Tauri SPA plus side IPC; Bun serves the SPA and the API from one loopback origin.
- Installed apps are cloned and built by the shell and approved per commit (ADR-0540); there is no Bun discovery or ready-frame membership for them. Hosted sync for an installed app's folder needs `/api/git/connect` scoped per app first (ADR-0521).
- No per-app permission prompt or device prompt. An app window runs as Epicenter: shared origin and session, and OS-granted browser device access. Native command grants remain window-scoped, keyed by app id for installed apps, until proposed ADR-0402 is implemented. Do not describe the capability file as a sandbox (ADR-0179, ADR-0334).
- Applications never choose the local transcription model. Settings (the `home` window) owns the one active model and its administration; the Folders window holds none of it; apps request transcription and may still choose their transcription route (ADR-0180).
- No new Settings pane and no global rail. Settings is one page; apps are installed, approved, updated, and opened from the Folders window (ADR-0540). A rail still needs a launchable list large enough to earn it (ADR-0189). Re-adding a Data pane means first deciding how a reader becomes a replica of somebody else's authority, which is an ADR, not a component.
- The loopback server always binds `127.0.0.1` and rejects every request without the per-launch token; this ships with the first server version, not later (ADR-0084).
- Do not turn an app-owned file bridge into a generic host command router, synced command table, or transport-adapter framework.
