# Epicenter

Read the [app README](README.md) for the existing desktop implementation and
the bundled-app path replacing installed apps. [Shared vocabulary](../../docs/CONTEXT.md) names the
chosen direction; the linked ADRs record its decisions. Local constraints below
protect the existing implementation while it remains in use.

## Shape

- Epicenter compiles its own pages from the closed `BuiltInApp` table in `src-tauri/src/lib.rs`: Settings (`home`) and the Folders window. It bundles Todos, Capture, Honeycrisp, and Whispering from their own folders under `apps/` through the closed `BundledApp` table in `src-tauri/src/bundled_apps.rs`, which names each app's page, default folder, window label, capability, and build. The installed-app path (`installed_apps.rs`, `open_installed_app`, the manifests and installer) stays compiled only until a later deletion; do not extend it, and do not list an installed copy of a bundled app.
- Epicenter is an application beside the others, not a shell above them (ADR-0209). Applications keep their own windows and the OS is the launcher and switcher, so do not build an in-app application switcher, a command palette over rows, or anything that indexes rows into an OS search index. Closing Epicenter must leave every other window running. The raw view ADR-0209 described returned as the Folders window over data folders on disk, and Epicenter opens to it (ADR-0537); the host-owned replica it once read stays deleted (ADR-0226). Do not reimport `src/inspect.ts`. Settings is the window labelled `home`; Home Chat is deleted.
- The Folders window opens a bundled app with `open_bundled_app`, an installed app with `open_installed_app`, and Settings with `open_home` (ADR-0537, ADR-0552). Each waits for the window's actual outcome. `open_bundled_app` is the one launch command for every bundled app and replaces `open_installed_app`; add a bundled app as a `BundledApp` row, never as another launch command.
- A bundled app's window is assigned its folder in Rust before the WebView exists: the app's fixed default under the folder root, which Open may create or recreate, or a direct child the Folders window listed, which must exist. It reuses that folder's one registry entry and is destroyed when it closes; do not route it through `ensure_window`, which hides Epicenter's own windows. No bundled app opens `so.epicenter` as its folder; Whispering alone is also permitted into it, for its AI connections.
- Every page is served by the one scheme handler, `src-tauri/src/scheme.rs`: Epicenter's own pages and each bundled app from `dist/<page>/` at `/<page>/`, and each installed app's build of one commit at `/apps/<app-id>/<commit>/`, which a window keeps until it is opened again (ADR-0588). Adding a page is a `BuiltInApp` or `BundledApp` entry plus its build (`build:bundled` for a bundled app), never another resolver, route, or server. The handler holds the containment (no link, nothing outside the directory) and the Content-Security-Policy, which hashes each document's inline scripts; a page served another way loses both.
- Keep document replicas owned by application windows, never by the host (ADR-0226, ADR-0227). Read [application composition](../README.md) and [folder contracts](../../packages/folder/README.md) before changing resource acquisition. App-owned authentication and UI seams use build conditions; do not add runtime detection to those seams.
- Native capabilities grant commands by window label, one file per kind of window: `folders.json`, `home.json`, `installed-app.json`, which selects `app:*` and gives every installed app the same grant (ADR-0570), `bundled-app.json`, which selects `todos:*`, `capture:*`, and `honeycrisp:*` and grants the folder plugin alone, and `whispering.json`, which selects `whispering:*` and grants only what Whispering's page calls. No bundled app's window gets folder history, `account_send`, or model administration. Every file is `"local": true`, because every page is on the scheme. Check the target window's grant when adding a native call; the rule is in the README. Proposed ADR-0402 would replace these files with one host-wide constant; that implementation has not landed.
- Native startup resolves `DesktopPaths` once, before recorder cleanup or any window opens. The recorder, the scheme, and every `epicenter` command the shell runs read that managed state; nothing resolves those paths again. The running bundle identifier scopes data and credentials; explicit directory overrides are resolved by native startup (ADR-0201, amended 2026-09-08).
- Every trusted app owns one directory under that root, `apps/<app-id>`, named by the id it is composed under (ADR-0201). Allocation is nominal: the host issues the id and creates nothing, and it reclaims nothing when an app leaves. Apps own their reverse-domain identifiers; the shared grammar validates them. Do not introduce a reservation list without an admission boundary that actually enforces it. Do not give a webview a path into any of it: reach is undecided, and the handle has no filesystem in it (ADR-0181).
- **The host-owned data plane is deleted** (ADR-0226, ADR-0227). Gone with it: the desktop store owner, the `honeycrispMirrorLens` that re-declared another application.s workspace id, the `src/folder/` markdown renderer and its SQLite projection (ADR-0207, ADR-0208), `src/inspect.ts` and the `/api/home/inspect` routes, the `/api/data` proxy and its observation socket, and the durable Home conversation rows. Do not rebuild any of them here. A host serves bundles and brokers credentials; a markdown mirror or a raw view belongs to whoever owns the authority those rows live in.
- Read the relevant application README before changing its file interpretation, save policy, or native ownership boundary.

## Refusals (do not reopen without a new ADR)

- No daemon `mount.ts` as the composition model; the mount path is CLI/projection for one app.
- No MCP for first-party in-process apps; MCP stays the boxed-app airlock (ADR-0073).
- No loose in-process TypeScript tool modules in v1; future scripting starts from an out-of-process runner unless a new ADR explicitly accepts unsafe developer-mode host imports.
- One way to serve a page: the `epicenter-app` scheme, in development as in a release. Do not add a dev server, a loopback server, or Tauri's asset protocol beside it (ADR-0561).
- While the installed-app path remains, installed apps are cloned and built by the shell and approved per commit (ADR-0540); the shell discovers none of them at startup. Bundled apps are built from local source and need no approval. A folder syncs to a hosted repository by `epicenter sync <dir> --to <namespace>/<name>` (ADR-0546).
- No per-app permission prompt or device prompt. An app window runs as Epicenter: shared origin and OS-granted browser device access, and every installed app's window gets the same native grant (ADR-0570). Do not describe the capability file as a sandbox (ADR-0179, ADR-0334).
- Applications never choose the local transcription model. Settings (the `home` window) owns the one active model and its administration; the Folders window holds none of it; apps request transcription and may still choose their transcription route (ADR-0180).
- No new Settings pane and no global rail. Settings is one page; apps are opened from the Folders window, and installed apps are also installed, approved, and updated there while that path remains (ADR-0540). A rail still needs a launchable list large enough to earn it (ADR-0189). Re-adding a Data pane means first deciding how a reader becomes a replica of somebody else's authority, which is an ADR, not a component.
- Do not turn an app-owned file bridge into a generic host command router, synced command table, or transport-adapter framework.
