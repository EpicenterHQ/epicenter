# Epicenter

One desktop application host. Bun serves the trusted SPAs, APIs, WebSockets,
and Home session; Rust owns native application mechanisms.

Design authority: [ADR-0190](../../docs/adr/0190-a-build-declares-which-epicenter-owns-its-data-not-which-window-it-runs-in.md) (a compiled application is a declared `dist/<id>` build; its "`epicenter-host` says the host owns its replica" half is withdrawn by ADR-0226, which a build no longer declares at all), [ADR-0209](../../docs/adr/0209-epicenter-is-the-raw-view-beside-its-applications-not-a-shell-above-them.md) (Epicenter is an application beside the others: it shows the data raw, the applications are the crafted views, and the OS is the launcher and switcher), [ADR-0189](../../docs/adr/0189-home-launches-applications-into-their-own-windows-and-stays-open-behind-them.md) (one launchable list, one Home-owned launch verb, per-application windows; its Home-as-shell framing is withdrawn by ADR-0209), [ADR-0179](../../docs/adr/0179-an-installed-app-is-an-inert-built-folder-admitted-through-one-static-artifact-boundary.md) (one static-artifact admission boundary for one immutable app catalog; supersedes ADR-0153), [ADR-0180](../../docs/adr/0180-epicenter-has-one-host-owned-active-local-transcription-model.md) (one host-owned active local transcription model), [ADR-0152](../../docs/adr/0152-epicenter-home-is-a-shell-above-workspaces.md) (what Home owns; read its title as history, since ADR-0209 withdrew "above"), [ADR-0151](../../docs/adr/0151-local-workspace-stores-use-owner-first-directories.md) (owner-scoped local stores), [ADR-0118](../../docs/adr/0118-epicenter-is-one-trusted-bun-hosted-spa-origin.md) (one trusted application origin), [ADR-0080](../../docs/adr/0080-the-super-app-is-a-desktop-host-cross-device-is-remote-access-to-the-session-not-a-per-app-capability-plane.md) (remote devices attach to the session, never to per-app endpoints), and [ADR-0113](../../docs/adr/0113-super-chat-session-commands-are-host-owned-transports-only-frame-them.md) (Home owns command semantics; transports only frame and deliver them).

## Shape

- `src/applications.ts` declares the compiled applications and composes what Home lists as launchable in one `{ id, title }` shape served at `/api/apps`. Its list is first-party only.
- Epicenter is an application beside the others, not a shell above them (ADR-0209). Applications keep their own windows and the OS is the launcher and switcher, so do not build an in-app application switcher, a command palette over rows, or anything that indexes rows into an OS search index. Closing Epicenter must leave every other window running. The raw-view pane ADR-0209 described is **deleted**, not broken: it opened a replica the host owned, and ADR-0226 withdrew that. Home has three panes now, Apps, Chat and Settings. Rebuilding a raw view is not a reimport of `src/inspect.ts`; an application on the store writes to its own client-owned store, so a reader that wants an application's rows has to become a replica of the authority that application uses, and that is a design nobody has written down yet.
- Home renders one row and calls one native verb (`launch_application`), which dispatches privately to a built-in app's own window or an `app-` window and settles on that window's real outcome rather than on having scheduled it. Rust validates the ID's shape only: catalog membership is Bun's alone (ADR-0179), and an ID naming no member resolves to a window Bun answers 404. Never re-derive the catalog in Rust, do not add a second launch command, and do not reuse ADR-0181's app-facing `openApp(appId)` name for it.
- A compiled application is exactly a `dist/<id>` build `COMPILED_APPLICATIONS` declares. `loadStaticAssets` loads every one and the server serves each below `/apps/<id>/` through the shared contained resolver, so adding one is a list entry plus a build script, never another asset field, resolver, or route handler. A declared application that did not build refuses the boot (ADR-0190). An admitted catalog member is served by that same loop and is not a lesser kind of page: its document is held in memory, gated behind a browser session, stamped with the auth bootstrap, and hashed into the one CSP, exactly like a compiled one. Serving an app's document straight off disk skips all four, and the app boots blank because the browser refuses its own start script.
- Every app window owns its document store and reaches one authority per signed-in account (ADR-0226, ADR-0227). Applications call `openApp(definition, { account })`. The package selects its default runtime and clipboard through `isTauri()` (ADR-0403); documents stay in the window's IndexedDB while native capabilities use host services. App-owned authentication and UI seams still use build conditions. Do not add runtime detection to those app seams or reintroduce a host-owned document replica.
- Current native capabilities grant commands by window label. Check the target window's grant when adding a native call. Proposed ADR-0402 would replace these files with one host-wide constant; that implementation has not landed. Same-origin HTTP to the Bun host needs no grant.
- Native startup resolves `DesktopPaths` once, before recorder cleanup or sidecar launch. The recorder reads that managed state; Bun receives required `dataDir` and `folderDir` fields in the boot frame. Desktop consumers must not resolve those paths again. The running bundle identifier scopes data and credentials; explicit directory overrides are resolved by native startup (ADR-0201, amended 2026-09-08).
- Every trusted app owns one directory under that root, `apps/<app-id>`, named by the id it is admitted or composed under (ADR-0201). Allocation is nominal: the host issues the id and creates nothing, and it reclaims nothing when an app leaves. Apps own their reverse-domain identifiers; the shared grammar validates them. Do not introduce a reservation list without an admission boundary that actually enforces it. Do not give a webview a path into any of it: reach is undecided, and the handle has no filesystem in it (ADR-0181).
- **The host-owned data plane is deleted** (ADR-0226, ADR-0227). Gone with it: the desktop store owner, the `honeycrispMirrorLens` that re-declared another application.s workspace id, the `src/folder/` markdown renderer and its SQLite projection (ADR-0207, ADR-0208), `src/inspect.ts` and the `/api/home/inspect` routes, the `/api/data` proxy and its observation socket, and the durable Home conversation rows. Do not rebuild any of them here. A host serves bundles and brokers credentials; a markdown mirror or a raw view belongs to whoever owns the authority those rows live in.
- **The `~/Epicenter` folder is a working copy, and the host writes and reads its files** (ADR-0337). `src/checkout.ts` and one route, `CHECKOUT_ROUTE`: `PUT` replaces the folder with the checkout the application rendered, `GET` hands back what the folder holds. A checkout is complete, so what it does not name is swept, and that sweep is filtered to row files, `kv.json`, `.epicenter/manifest.json`, and the `AGENTS.md` a pull generates: a person's own `README.md` beside their notes is theirs, and a `drafts/` they keep is too. The host holds no rows and decodes nothing, not even the manifest. ADR-0271's continuous render and its one-way rule are withdrawn, and with them the refusal to read the folder that served them. What stays refused is a host that INTERPRETS a file: nothing here parses frontmatter, and nothing here reaches a row.
- `src/host.ts` composes optional boxed stdio MCP tools and optional read-only local sources into one workspace idd `ToolCatalog`. It opens no store and owns no data directory. Its conversation transcript is in memory for the session: the host holding a durable transcript needs a document of its own, and nobody has decided it should have one.
- Local sources remain host-owned and are never remote routes or capabilities.
- Command semantics belong to the host session, not the WebSocket adapter. Chat sends, direct invocations, approval answers, and later palette or voice commands must route through one host-owned session command API.

## Refusals (do not reopen without a new ADR)

- No daemon `mount.ts` as the composition model; the mount path is CLI/projection for one app.
- No MCP for first-party in-process apps; MCP stays the boxed-app airlock (ADR-0073).
- No loose in-process TypeScript tool modules in v1; future scripting starts from an out-of-process runner unless a new ADR explicitly accepts unsafe developer-mode host imports.
- No bundled Tauri SPA plus side IPC; Bun serves the SPA and the API from one loopback origin.
- Epicenter admits inert built app folders and never installs dependencies, runs an app's build system, or reads application source. A folder from a publisher URL, a self-hosted builder, a local developer build, or offline media enters through the same boundary with the same authority (ADR-0179).
- No registry, publisher identity, artifact signing, or update mechanism. ADR-0179 decides admission only; anything downstream of it needs its own ADR.
- No per-app permission, capability grant, or device prompt. An app window runs as Epicenter: shared origin and session, and OS-granted browser device access. Native command grants remain window-scoped until proposed ADR-0402 is implemented. Do not describe the capability file as a sandbox (ADR-0179, ADR-0334).
- Applications never choose the local transcription model. Home owns the one active model and its administration; apps request transcription and may still choose their transcription route (ADR-0180).
- No new Home pane, no global rail, and no installation, update, or removal UI. Home has Apps, Chat, and Settings. A rail still needs a launchable list large enough to earn it, and app management still needs real operations before it needs a screen (ADR-0189). Re-adding a Data pane means first deciding how a reader becomes a replica of somebody else's authority, which is an ADR, not a component.
- The loopback server always binds `127.0.0.1` and rejects every request without the per-launch token; this ships with the first server version, not later (ADR-0084).
- No HTTP command route, Tauri IPC command path, stdio command protocol for the browser UI, generic synced command table, or transport-adapter framework until a real second consumer earns it. The current WebSocket is a session adapter, not the architecture.
