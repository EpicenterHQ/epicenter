# 0098. Every Local Mail concept a human acts on round-trips through Gmail API state

- **Status:** Accepted
- **Date:** 2026-07-01
- **Amended by:** [ADR-0197](0197-a-mirrors-corpus-version-names-its-artifact-and-only-the-app-knows-when-one-is-ready.md) at the mechanical-enforcement clause only: the `SCHEMA_VERSION` drop-and-rebuild that punished local-only state in mirror tables is withdrawn. The round-trip rule itself is untouched. Also amended by [ADR-0198](0198-a-durable-local-mail-write-is-a-per-message-label-assertion-in-a-sibling-intent-database.md) at the refusal of local-only state only: durable local *intent* is admitted in one bounded shape, a per-account partial map from (message id, label id) to want, held in a sibling `intent.db` until Gmail confirms it and then deleted. It is displayed as a pending request, never as a fact about the mailbox, and it is not a second source of mail truth. The refusals of snooze, send-later, local tags, and local drafts stand.
- **Relates:** [ADR-0080](0080-the-super-app-is-a-desktop-host-cross-device-is-remote-access-to-the-session-not-a-per-app-capability-plane.md) (cross-device is a remote session, not per-app phone code, so the phone reads mail in the phone's own mail app), [ADR-0081](0081-per-upstream-oauth-concurrency-decides-mirror-topology.md) (each device holds its own mirror against Google directly), [ADR-0082](0082-local-mail-syncs-by-push-free-history-list-polling.md) (push-free `history.list` polling; the mirror is only ever written from what Gmail returned, and its write-through clause is withdrawn by [ADR-0199](0199-one-account-reconciler-is-local-mails-only-gmail-writer.md)), [ADR-0083](0083-apps-email-is-refused-local-mail-is-the-only-gmail-client.md) (Local Mail is the only Gmail client)

## Context

Local Mail ships no phone code: the phone client is Gmail's own app (ADR-0080 keeps cross-device as a remote session rather than per-app reach, and ADR-0083 refused the webmail SPA that could have filled that slot). That only stays consistent if every state change a human makes on the desktop lands in Gmail, where the phone app can see it. The mechanics were already decided when this was written: per-device mirrors against Google directly (ADR-0081) and write-through, Gmail first, mirror folded in after (ADR-0082). Half of that has since changed. ADR-0199 withdrew write-through; a triage act is now a durable local assertion (ADR-0198) that the account's one reconciler delivers. What did not change is the part this record depends on: the state still ends up in Gmail, and the mirror is still only ever written from what Gmail returned. What had no durable home was the product refusal those mechanics serve. Until now it lived as one row of a deletable Draft spec's decision table, which is a homeless place for a load-bearing invariant: specs are deleted when the work lands.

## Decision

**Every Local Mail concept a human acts on must be expressible as, and round-trip through, Gmail API state. Local Mail refuses local-only mail state until a future ADR accepts device-bound behavior with explicit failure semantics.**

Feature by feature:

- **Tags** are allowed only as real Gmail labels (`labels.create` plus `messages.modify`), never a local column. A tag applied on the laptop must be visible and removable on the phone.
- **Drafts** are expressible (`drafts.create`, `drafts.update`, `drafts.send`) and allowed as Gmail-backed operations. (This clause originally said "within write-through scope"; write-through is withdrawn by ADR-0199, and ADR-0198 refuses a draft held locally as durable intent. What stays allowed is a draft that is Gmail's.)
- **Read/unread** is the `UNREAD` label and must round-trip. This is why the UI never ships a read state that cannot reach Gmail: an inbox whose read state stays local leaves every handled message unread on the phone. (Originally "this is why the UI ships only with write-through". The requirement was always that the state reaches Gmail, not that it reaches Gmail synchronously from the click; under ADR-0198/0199 it reaches Gmail through a durable assertion the reconciler delivers.)
- **Snooze** is refused. The Gmail API has no snooze surface. Emulating it with label moves plus a local timer makes the state expressible but the behavior device-bound: a laptop asleep at wake time means mail never resurfaces, and the phone can neither see nor cancel the pending snooze.
- **Send-later** is refused hardest. It is not in the API, and a silently unsent email is a commitment breach, not a UX gap.
- **Derived or advisory local data** (agent notes, triage suggestions, search annotations) is allowed when it is rebuildable and never gates handled-semantics.

The rule of thumb: any state a human acts on must round-trip through Gmail.

## Consequences

- The phone story holds with zero Local Mail phone code: whatever the desktop does, Gmail's own app reflects it.
- Enforcement is partly mechanical. This record originally claimed a mechanical guard: the schema's drop-and-rebuild on a `SCHEMA_VERSION` bump destroyed any state stored in mirror tables, so a violation that smuggled precious local state into the mirror was punished at the next bump. **ADR-0194 withdrew that guard, and ADR-0197 keeps it withdrawn.** A version bump now names a new artifact and retains the predecessor; opening destroys nothing, so nothing is punished later. What replaces it is earlier and more visible: local-only state has to appear in the reviewed table declarations to exist at all, which is where the violation is now caught.
- **Withdrawn warning: a sibling overlay is no longer the escape hatch this record watches for.** This consequence used to end "Overlay tables beside the mirror remain the escape hatch this ADR exists to catch in review", and it named the mirror's only writer as `sync.ts` plus the write-through cores. Both statements are superseded. [ADR-0198](0198-a-durable-local-mail-write-is-a-per-message-label-assertion-in-a-sibling-intent-database.md) accepts exactly one sibling store, a durable `intent.db` holding a bounded partial map of label assertions, and [ADR-0199](0199-one-account-reconciler-is-local-mails-only-gmail-writer.md) makes one per-account reconciler the only Gmail writer and the only thing that retires an assertion. The rule this record actually protects is unchanged and is what a reviewer should still apply: no local store may hold mail state that Gmail does not end up owning. An assertion qualifies because it names a Gmail label id and exists in order to stop existing; a tag column, a local read flag, or a second map that outlives delivery does not.
- Snooze and send-later stay off the roadmap regardless of demand until the revisit trigger fires.
- Revisit trigger: an always-on device that can own timers (the super-app desktop host of ADR-0080, or a home server) would make snooze semantics honest, because the timer survives a laptop lid and cancellation has one home. That is the earliest credible reopen, and it takes a new ADR accepting device-bound behavior with explicit failure semantics.

## Considered alternatives

- **Emulate snooze with label moves plus a local timer.** Rejected: the state round-trips but the behavior does not; a sleeping laptop silently breaks the "it comes back" promise, and the phone cannot see or cancel it.
- **A local tags column beside `label_ids`.** Rejected, and still rejected under ADR-0198: it forks the labeling model into one the phone can never see, and unlike an assertion it has no end state in which Gmail owns it. The original second reason (the mirror's drop-and-rebuild would destroy it anyway) is gone under ADR-0197, which retains the predecessor instead of destroying it. The first reason was always the load-bearing one.
- **Ship read/unread UI before the state can reach Gmail.** Rejected: reading mail flips human-meaningful state; if that flip cannot reach Gmail, the phone shows as unread what the user already handled. (Originally phrased as "before write-through". The bar is that the flip is durably recorded and will reach Gmail, which ADR-0198's assertion satisfies without a synchronous write.)
