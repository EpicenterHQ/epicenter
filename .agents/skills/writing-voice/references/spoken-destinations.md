# Writing That Will Be Heard

Hear what the writing is doing, then judge it by what this piece needs.
For narration, examine the complete spoken experience; for a local concern,
use the whole piece as context while keeping the edit within its requested scope.
The destination workflow owns proposals, selections, and saved changes.

A listener encounters the words in order. Check what they need to understand
each turn, including premises supplied visually by a title, heading, diagram,
image, or code example. Put indispensable context into the spoken prose when
the destination will not communicate it otherwise. A visual can still help
the reader; it need not be removed or described exhaustively.

Let the opening invite attention in the author's register and make a promise
the piece keeps. Breath, clause length, and sentence load are clues to friction,
not limits to enforce mechanically. Follow the argument, scene, or question
through to its ending without imposing a reveal, moral, or summary.

For a short spoken surface, consider how soon the listener has something
concrete to hold, whether explanations repeat the same work, and whether the
length serves the thought. Flag a duration concern in relation to its intended
outlet; do not impose a universal word count, a two-second sentence, or clickbait.
Timing and delivery can reveal a wording problem, but should not conceal one.

## The Purpose Changes The Judgment

These invented samples illustrate the same listening attention serving different
work. They are not required response formats or additional editing stages.

**Braden:** Give this journal passage an ear pass, but keep how uneventful the
afternoon was.

**Original**

> We sat there for a while. Nobody really had much to say. Then we ordered
> another coffee and sat there for a while longer.

**Agent:** I’d keep this as it is. The repeated “sat there for a while” makes
the afternoon feel unhurried. Cutting it would remove part of what you’re
describing.

**Braden:** This page is going to be narrated. Check whether it works aloud.

**Original**

> The lower layers return a result. The diagram below shows where that chain ends.

The accompanying diagram in this sample:

```txt
smaller operation → Result → caller → Result → event handler → user-facing effect
```

**Suggested**

> The lower layers return a result. Each caller can pass it upward until it
> reaches the event handler, where the outcome becomes something the user can see.

**Agent:** The original hands the explanation to the diagram. This version
gives the listener the relationship in words; the diagram can still make it
easier to see.
