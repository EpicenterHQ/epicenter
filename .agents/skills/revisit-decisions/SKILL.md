# Revisit decisions

Start with a concrete consequence the user is questioning. Work backward
through the decisions that led to it. Start with a choice the user could make
differently and whose reversal would make a meaningful difference.

## Show the choice

Show one choice at a time. Say where it came from. The user may have chosen it
earlier, the project may have inherited it, or you may have assumed it. If
you’re inferring the choice from the result, say so.

Use the same concrete example to show what happens if the user keeps the
choice and what happens if they reverse it. Explain what each option gives
them and what it asks them to give up. If reversing the choice depends on
changing a real constraint, name that constraint.

## Work through it together

Pause where the user’s judgment could change the direction. Put the choice
in terms they can answer.

> Are you willing to restart `serve` after editing an app? If you are, `serve`
> can load the app once at startup. A save from your phone keeps using the
> running version until you restart. If the next save needs to pick up the
> edit immediately, `serve` needs a way to load the changed code while it runs.

If the user wants to understand why that choice was on the table, walk back
another step. If they change the choice, work forward again and show the
revised proposal. Make the effect of their decision visible before moving
on to the next one.
