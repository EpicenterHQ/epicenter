# The machine: one engine, found folders, moves, and restore

**Date**: 2026-11-04
**Status**: Draft
**Owner**: Epicenter

## One sentence

Every program on a machine shares one engine in `~/.epicenter`, each app
signs in as its site, Epicenter finds folders by looking in `~/Epicenter` instead of keeping a
list, and can move a folder or restore one from the account.

Decisions: [ADR-0713](../docs/adr/0713-one-epicenter-engine-per-machine-syncs-every-apps-folder.md)
(one engine), [ADR-0714](../docs/adr/0714-a-files-extension-decides-how-every-folder-merges-it.md)
(merge rule), [ADR-0715](../docs/adr/0715-the-epicenter-app-browses-every-folder-and-document-a-person-has.md)
(Epicenter browses), [ADR-0718](../docs/adr/0718-epicenters-machinery-on-a-machine-lives-in-a-hidden-home-every-program-reads.md)

(`epicenter move`, join), and the vision's Planned section.

## Why now

Phase 1 made every folder's path derivable. The machine still keeps a list of
folders in the global Git configuration, installs the CLI by a symlink in
`~/.local/bin`, relies on the system's `git` and `git-lfs`, signs in once per
program, and offers no way to move a folder or restore one from the account.

| 5 | The account's folders beside the local ones in Epicenter, and "Restore" cloning or joining one at its derived path | B |
| 6 | Sync under a login agent, independent of the Epicenter window | B |
| 7 | The merge rule by extension: a binary-extension list goes to LFS, everything else merges as text, the server refuses an oversized file outside LFS | B |

Each wave closes with a three-seat review (two Codex, one Claude). Each
commit builds, passes its own tests, and leaves every app working.
