# Repository engine, slice 1: the core in Bun

In-flight spec for ADR-0692 (`docs/adr/0692-every-write-is-a-live-commit-on-its-parent-taken-through-the-repositorys-server.md`, Proposed). Read the ADR first; it is the design. This slice builds the engine and server core as one new package, tested end to end in Bun with no browser and no Cloudflare. Later slices add the browser driver and an app (slice 2) and the Durable Object, Artifacts, read endpoints and CLI (slice 3).

## Package

New package `packages/repository` (`@epicenter/repository`), following `packages/folder`'s conventions: `"type": "module"`, exports pointing at `src/*.ts`, `typecheck` (`tsc --noEmit -p tsconfig.json`) and `test` (`bun test`) scripts, `tsconfig.json` extending `../../tsconfig.dom.json` with `types: ["bun"]`, catalog dependencies (`typebox`, `wellcrafted`, `yaml`). No `console.*` in library code (`wellcrafted/logger`). Expected failures are `Result`s (`wellcrafted`); see the repository's `error-handling` and `typescript` skills. Do not modify `packages/folder` or any app in this slice.

Exports:
- `.` the app API (`defineApp`, handle types, `slug`, `timestamp`) and the engine (`openRepository`).
- `./server` the server core.
- `./merge` the Epicenter merge (pure).
- `./bun` the `bun:sqlite` driver and a local Git store for tests and the CLI.

## Pieces

1. **Templates** (`src/templates.ts`). Port and harden `spike-scratch/templates/templates.ts` (absolute path: `/Users/braden/.claude/worktrees/epicenter-overnight/spike-scratch/templates/`): compile, match, build, overlap detection, `Params<T>` type inference. Names must be identifiers.
2. **`defineApp`** (`src/define.ts`). Maps identifier names to `{ path, schema }` (Markdown, path ends in `.md`) or `{ path, blob: { types, maxSize? } }` (path not ending in `.md`). Refuses bad names, bad templates and overlaps at definition time. Produces the lens: per name, a SQL view definition and the handle type. Typed so IntelliSense shows the parameter object per handle and the schema's fields (`Static` from TypeBox); a template with no segments takes no parameters.
3. **Markdown codec** (`src/markdown.ts`). Split a file into frontmatter and body; parse frontmatter with `yaml` into a plain object; refuse unparseable frontmatter. Write: when fields change, edit the YAML document in place (keep the current key order, append new keys, keep comments where the `yaml` Document API allows), never reformat untouched keys. LFS pointer parse and write.
4. **The Epicenter merge** (`src/merge.ts`). Port `spike-scratch/merge-spike/merge.mjs` (absolute path: `/Users/braden/.claude/worktrees/epicenter-overnight/spike-scratch/merge-spike/`) to TypeScript, Markdown only (settings are frontmatter of a root record, so no JSON kind). Rules per the ADR: frontmatter by key, current wins and the incoming value is recorded in `dropped`; body by line, neighboring lines don't conflict, word-level second pass, same-point insertions both kept (current first); two creates at one path merge fields and keep both bodies; delete versus edit signalled. `withMarkers` for the people policy (Git markers with a base section, server-order labels, never nested). Keep its example and property tests, and a linear-space or bounded diff for large notes.
5. **Device engine** (`src/engine/`). `openRepository({ app, driver, transport, device })`. One SQLite database, three STRICT engine tables named with a slash (`"epicenter/files"`, `"epicenter/outbox"`, `"epicenter/meta"`) as in the ADR's Devices paragraph. `body` is a VIRTUAL generated column from plain SQL; `fields` is written by the engine in the same statement as `text` (Bun's SQLite has no registered functions; keep one write path). Lens views and indexes are TEMP views created on open. Handles per the ADR's app API: note handles `get`, `list`, `create`, `write`, `move`, `delete`; blob handles `put`, `get`, `url`, `list`, `delete` (bytes through an injected `BlobStore` interface; an in-memory store for tests). Reads are synchronous over SQL; `repo.live(sql)` re-runs on any change and compares results. `repo.batch(b => ...)` builds a write-only batch synchronously and resolves to one outcome per change. Writes apply locally at once, enter the outbox in one transaction, and are sent in order with `(device, n)`; acknowledgments and server changes rebase pending edits with the merge.
6. **Server core** (`src/server/`). A transport-agnostic `RepositoryServer` with its own SQLite (overlay, batches, devices, receipts, path history, state) and a `GitStore` interface (read tree, read blob, write blobs/tree/commit, compare-and-swap `main`). Applies batches all or nothing with the people or agent policy (agent = a flag on the connection for this slice); outcomes `applied` (with per-file overlaps, dropped, editKept, movedTo, text), `need-base`, `expired`, `refused`; per-device numbers with recorded outcomes; stamps a user id given by the connection; keeps a week of path history (creates, moves, deletes) and refuses a move onto a taken path; commits changed files when asked and on a timer you can drive in tests, with an `Epicenter-Seq` trailer and compare-and-swap; clears the overlay only up to what Git holds. Keep the overlay-versus-commit-before-acknowledge choice behind one function boundary; a deployed spike is measuring it.
7. **Agent push** (`src/server/push.ts`). Given a pushed commit already in the `GitStore`: merge-base with `main`, net diff to one batch (writes, moves from rename detection, deletes), agent policy, pushed commit as a parent of the result, refusal commits the overlay first. Also refuse unparseable frontmatter, notes over 1 MB, and binaries outside LFS.
8. **Bun adapters** (`src/bun/`). A `bun:sqlite` driver behind the driver interface; a local `GitStore` over a bare repository (use the `git` CLI or isomorphic-git, already a workspace dependency of `packages/folder`); an in-process transport.

## Tests (bun test) that define done
- Templates, codec, merge: unit and property tests (port the spikes').
- Type tests with `@ts-expect-error`: missing segment, wrong field type, `put` absent on note handles, no reads inside `batch`.
- End to end, in process, two devices plus a server plus a local Git store: an edit appears on the other device; an offline edit on each device merges on reconnect; a true overlap becomes a marker block for people and a refusal for an agent batch; two creates at one path merge; a move is followed by a stale edit and a move onto a taken path is refused; a delete versus an edit keeps the edit for people; `repo.settings.set` style writes to a root record merge by key; append from two devices keeps both in server order; a retried batch returns its recorded outcome; `need-base` round trip; `expired` after the window; a note and its blob in one batch; the overlay clears after a commit and the commit carries the right sequence; an agent push that overlaps is refused and a clean one lands with its commit as a parent.
